

## 법적 검토 결과

2026년 2월 문화체육관광부가 발간한 「생성형 AI 저작물 학습 공정이용 안내서」에 따르면:

- **AI가 뉴스 기사를 요약하여 제공하는 서비스**는 언론사의 시장을 교란할 수 있어 **공정이용으로 인정받기 어렵다**는 입장입니다.
- 특히 원문을 크롤링하여 요약·재구성 후 자체 서비스에서 제공하는 행위는 저작권 침해 리스크가 높습니다.

**하지만**, 이 프로젝트에서 이미 수집된 뉴스 데이터(DB에 저장된 `news` 테이블)를 기반으로 **주제별로 분류·재분석하여 인사이트 형태로 제공**하는 것은 기존 인사이트 DIY와 동일한 패턴이며, 원본 출처를 명시하고 원문 링크를 제공한다면 리스크를 줄일 수 있습니다.

따라서 **외부 웹에서 새로 기사를 크롤링하는 방식은 피하고**, 이미 DB에 수집된 뉴스를 AI가 주제별로 분석·요약하여 카드로 보여주는 방식으로 구현하겠습니다.

---

## 구현 계획: "트렌드 브리핑" 페이지

뉴스 DIY와 인사이트 사이에 **트렌드 브리핑** 페이지를 추가합니다. 사용자가 주제를 입력하면 DB의 뉴스를 분석하여 요약 카드들을 생성하고, 카드 클릭 시 상세 분석 내용을 같은 페이지 내에서 펼쳐 보여줍니다.

### 1. Edge Function 생성: `trend-briefing`

- DB에서 최신 뉴스 200건 조회
- AI(Gemini 2.5 Flash)에게 사용자 주제와 뉴스 목록을 전달
- AI가 관련 뉴스를 그룹화하여 3~8개의 트렌드 카드를 JSON으로 반환
- 각 카드: `title`, `summary` (2~3줄 요약), `detail` (상세 분석), `sources` (출처 뉴스 제목+URL+source+date 배열)
- 기존 보안 패턴 적용 (auth 검증, 프롬프트 인젝션 차단)

### 2. 프론트엔드: `src/pages/TrendBriefing.tsx`

- 검색 입력 + 버튼 (DiyNews와 유사한 레이아웃)
- 결과: 카드 그리드 (제목, 요약, 출처 수 표시)
- 카드 클릭 → Dialog 또는 Accordion으로 상세 분석 + 출처 목록 표시
- 출처는 카드 하단에 뉴스 소스명 + 날짜로 표기

### 3. 라우팅 및 네비게이션 업데이트

- `ViewType`에 `"trend-briefing"` 추가
- `/trend-briefing` 라우트 추가 (뉴스 DIY와 인사이트 사이)
- 네비게이션 버튼 추가 (아이콘: `Zap` 또는 `TrendingUp`)
- `config.toml`에 함수 등록
