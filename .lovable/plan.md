현재 문제 원인은 코드와 저장 데이터 기준으로 꽤 명확합니다.

1. 특허 링크가 계속 막히는 이유
- 현재 특허 데이터 71건은 모두 `verified=true`처럼 저장돼 있지만, 실제 링크는 원문 특허 페이지가 아니라 `google.com/search?q=patent+번호` 형식입니다.
- 즉, 지금은 “진짜 원문 검증”이 아니라 “형식이 그럴듯한 특허번호 + 구글 검색 링크”를 검증된 것처럼 처리하고 있습니다.
- 그래서 미리보기 iframe 환경에서는 Google 보안 헤더 때문에 `ERR_BLOCKED_BY_RESPONSE`가 나고, 이것은 코드만으로 완전히 우회할 수 없습니다.

2. 논문 카드가 클릭돼도 아무 창이 안 뜨는 이유
- 현재 저장된 research 데이터 179건은 전부 `linkVerified=false` 상태입니다.
- 프론트엔드가 `linkVerified=false`면 클릭을 막도록 되어 있어서, 지금 동작은 버그라기보다 “검증 실패 링크를 열지 않게 막는 로직”이 작동한 결과입니다.
- 실제 샘플 데이터를 보면 403 차단으로 판정된 논문이 많습니다.

3. 트렌드 브리핑 출처 링크가 안 열리는 이유
- 브리핑 히스토리에는 과거 카드가 저장되어 있는데, 일부는 `linkVerified` 메타데이터가 없거나 Google News 래퍼 URL 같은 불안정한 링크를 그대로 갖고 있습니다.
- 현재 UI는 검증된 링크만 열도록 바뀌어 있어서, 과거 데이터는 자연스럽게 비클릭 상태가 됩니다.

4. 더 근본적인 문제
- 현재 “링크 검증”은 서버에서 1회 fetch 후 404/403/본문 키워드 정도만 보는 휴리스틱입니다.
- 게다가 특허는 예외적으로 이 검증마저 건너뛰고 구글 검색 URL을 강제로 `verified=true`로 처리하고 있습니다.
- 또한 `news` 테이블 타입을 보면 링크 검증 메타데이터 컬럼이 없어서, 뉴스 검증 결과가 DB에 구조적으로 축적되지 못하고 있을 가능성이 큽니다.

무엇이 가능하고, 무엇이 불가능한가
- 100% 절대 보장은 불가능합니다. 어떤 외부 사이트는 서버 fetch에는 200을 주고 실제 브라우저에서는 쿠키, 지역, 봇 방지, 캡차, 속도 제한 때문에 나중에 막을 수 있습니다.
- 하지만 “검증 통과한 링크만 노출하고, 조금이라도 불확실하면 링크를 아예 제거하고 제목+요약만 보여주는 방식”으로는 충분히 강하게 만들 수 있습니다.
- 즉, “완전한 우주적 보장”은 불가능하지만, “404/403/차단/검색 래퍼 링크를 시스템적으로 최대한 배제”하는 것은 가능합니다.

구현 계획

1. 가짜 양성(false positive) 링크 로직 제거
- 특허의 Google Search fallback을 제거합니다.
- `형식만 맞는 특허번호 => verified=true` 처리도 제거합니다.
- 검색 페이지, Google News 래퍼, 중간 리다이렉트 페이지는 앞으로 검증 통과 대상으로 인정하지 않습니다.

2. 링크 검증 파이프라인을 전체 콘텐츠 타입에 공통 적용
- 뉴스, 논문, 특허, PRM/TRM 출처, 트렌드 브리핑 출처에 동일한 검증 유틸을 적용합니다.
- 검증 단계:
  1) URL 정규화
  2) 리다이렉트 추적 후 최종 URL 확인
  3) Google 검색/뉴스 래퍼/차단 known-host 거부
  4) 404/403/soft-404/captcha/paywall/empty page 패턴 탐지
  5) 제목/저널/특허번호/출원인 등 힌트와 본문 메타데이터 대조
  6) 통과한 링크만 `verified=true`
  7) 실패 시 링크 제거 + 차단 사유 + 1줄 설명 저장

3. 데이터 저장 구조 보강
- `news` 테이블에 링크 검증 메타데이터를 저장하도록 마이그레이션을 추가합니다.
- 예: resolved URL, verified 여부, status code, blocked reason, verified at timestamp.
- 이렇게 해야 뉴스 수집 시 검증 결과가 누락되지 않고, 이후 트렌드 브리핑/뉴스 페이지/카테고리 분석에서도 같은 결과를 재사용할 수 있습니다.

4. UI 동작 통일
- 특허/논문/뉴스/트렌드 브리핑/로드맵 모두 “검증 통과 원문만 클릭 가능”으로 통일합니다.
- 검증 실패/불확실 출처는 클릭 불가 카드로 보여주고:
  - 제목
  - 출처명
  - 날짜
  - 1줄 설명
  - 실패 사유
  만 표시합니다.
- 특히 과거 브리핑 히스토리도 새 규칙에 맞게 다시 생성하거나 마이그레이션해서, 예전 데이터 때문에 클릭이 안 되는 상태를 정리합니다.

5. 특허/논문 데이터 정제 및 재생성
- 현재 저장된 특허는 “실제 원문 검증 없이 생성된 항목”이 섞여 있으므로 전수 재검증 후, 검증 실패 항목은 삭제합니다.
- 논문도 403/blocked로 남은 항목은 클릭 링크를 제거하고, 실제 접근 가능한 원문/랜딩 페이지가 확인되는 것만 링크를 남깁니다.
- 필요하면 AI가 추정 생성한 레코드를 그대로 쓰지 않고, 검증 가능한 출처가 없는 항목은 버리도록 바꿉니다.

6. 재수집/백필(backfill)
- 수집 함수와 분석 함수를 수정한 뒤, 뉴스 재수집 → 시장 분석 재생성 → 브리핑 히스토리 재생성 순으로 백필합니다.
- 이 단계가 필요합니다. 코드만 고치면 기존 DB의 잘못된 링크는 그대로 남기 때문입니다.

기술 상세
- 수정 대상 프론트엔드: `Patents.tsx`, `Research.tsx`, `TrendBriefing.tsx`, `RoadmapTimeline.tsx`, `NewsView.tsx`, 공통 link validation 유틸
- 수정 대상 백엔드 함수: `crawl-news`, `analyze-market-data`, `analyze-dashboard`, `trend-briefing`, 필요 시 `analyze-news-category`
- DB 작업: `news` 테이블 링크 검증 컬럼 추가 마이그레이션
- 검증 정책 핵심: “검증 안 되면 절대 링크를 열지 않음”

검증 결과로 기대되는 변화
- 특허 페이지: 구글 차단 페이지로 보내는 링크 제거
- 논문 페이지: 지금처럼 아무 창도 안 뜨는 이유가 명확히 데이터로 표시되고, 진짜 검증된 논문만 클릭 가능
- 트렌드 브리핑: 과거/신규 카드 모두 출처가 검증되면 열리고, 아니면 제목+설명만 표시
- 전체적으로 404/403/차단/검색 래퍼 링크가 크게 줄어듭니다

주의할 점
- 미리보기 iframe에서는 일부 외부 사이트가 원래 차단됩니다. 그래서 최종 검증 기준은 “미리보기에서 열리는가”가 아니라, “백엔드 검증을 통과했고 실제 원문 URL인가”로 잡아야 합니다.
- 그래도 published top-level 환경에서는 실제 사용자 경험이 미리보기보다 훨씬 정확합니다.

승인해주시면 이 계획대로 실제 수정, 마이그레이션, 데이터 재생성까지 진행하겠습니다.
